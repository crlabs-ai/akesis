# Official Akesis Terminology

| Term | Official Definition |
| :--- | :--- |
| **CI Failure** | An event where an automated continuous integration pipeline terminates with a non-zero exit code or error status. |
| **Incident** | A tracked Akesis entity representing an ingested CI failure event for a specific repository, branch, and commit. |
| **Log Stream** | The raw stdout/stderr output emitted by a failed CI workflow job. |
| **Diagnosis** | The structured output of log analysis, containing root cause category, failed file paths, line numbers, and error signature. |
| **Remediation** | The end-to-end workflow of diagnosing a failure, generating a code fix, validating it, and delivering a Pull Request. |
| **Patch** | A unified git diff (`.diff` / `.patch`) representing minimal code modifications generated to resolve a diagnosis. |
| **Sandbox** | An isolated, ephemeral Docker container environment where a patch is applied and tested against the failure. |
| **Validation** | The automated execution of the build, lint, or test command inside the sandbox to verify clean compilation. |
| **Confidence Score** | A normalized float ($0.0$ to $1.0$) generated by the agent runtime representing certainty in the diagnosis and fix. |
| **Human Approval** | The explicit action taken by a developer reviewing and merging the Akesis-generated Pull Request. |
| **Quarantine** | The action of isolating a non-deterministic (flaky) test to prevent it from blocking the main delivery pipeline. |
| **Agent Runtime** | The deterministic state-machine coordinator managing LLM prompts, tool invocations, and validation checks. |
| **Workflow** | The sequence of tasks executed for a single incident (Ingest $\rightarrow$ Diagnose $\rightarrow$ Generate $\rightarrow$ Validate $\rightarrow$ Deliver). |
