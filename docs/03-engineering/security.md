# Security Policy & Architecture Standards: Akesis

---

## 1. Secrets Management
*   **Zero Hardcoding:** No API tokens, webhook secrets, or database credentials may ever be committed to the repository.
*   **Static Scanning:** Automated CI workflows run `gitleaks` on every pull request to detect accidental credential exposure.
*   **Runtime Vaulting:** Environment variables must be loaded securely from AWS Secrets Manager / HashiCorp Vault.

---

## 2. Execution Sandbox Hardening (Critical)
The sandbox environment executes code generated by AI models. It is treated as an **untrusted security boundary**:
1.  **Dropped Privileges:** Containers must run as an unprivileged non-root user (`uid: 1000`).
2.  **Linux Capabilities:** Drop all default capabilities (`--cap-drop ALL`).
3.  **Filesystem Isolation:** Root filesystem mounted as read-only (`--read-only`); temporary compilation scratch directories mounted in memory (`tmpfs`).
4.  **Network Isolation:** Network access is disabled (`--network none`) during test/build execution to prevent data exfiltration.
5.  **Resource Limits:** Hard limits enforced per sandbox: `CPU: 1.0 core`, `Memory: 512MB`, `Timeout: 60s`.

---

## 3. Prompt Injection Defenses
CI error logs and repository code originate from untrusted external sources. To prevent prompt injection attacks:
*   Untrusted logs are encapsulated within strict XML/JSON data tags in prompt templates.
*   System prompts explicitly command the model to treat log contents purely as string data, never as executive instructions.
*   Outputs are constrained to strict Pydantic JSON schemas.
